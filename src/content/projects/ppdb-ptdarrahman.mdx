## Ringkas

PPDB dan company profile untuk Pesantren Tahfidz Qur'an dan Digital Ar-Rahman. Satu repo menaungi website publik, portal pendaftaran santri, backoffice panitia, panel superadmin, dan WA gateway. Semua frontend membaca satu Core API, jadi status pendaftaran, keputusan panitia, dan konten publik berasal dari satu data model.

## Konteks dan batasan

Seleksi santri punya beberapa tahap yang saling mengunci: kuesioner kesehatan, verifikasi dokumen, ujian TIU, wawancara, pembayaran, lalu penerbitan dokumen resmi. Kalau tiap tahap disimpan di aplikasi terpisah, status peserta akan tersebar dan rawan tidak sinkron. Karena itu bentuknya monorepo dengan satu API pusat, bukan kumpulan service yang saling memanggil.

Dua rute publik (`/kuitansi/:id` dan `/loa/:registrationNo`) harus bisa dibuka tanpa login karena dipindai lewat QR code. Ini membatasi desain auth: data yang perlu diverifikasi publik tidak boleh bergantung pada sesi pengguna.

## Alur pendaftaran

1. Calon santri mengisi formulir tujuh tahap. Tidak ada field jenjang, jadi satu alur berlaku untuk semua pendaftar.
2. Kuesioner kesehatan berisi sepuluh soal dan diverifikasi.
3. Panitia memverifikasi dokumen yang diunggah di backoffice PPDB.
4. Ujian TIU berjalan di Safe Exam Browser. Google Apps Script mengirim nilai kembali ke API lewat webhook.
5. Peserta booking sesi 1:1 Tahfidz dan wawancara.
6. Pembayaran pakai QRIS dinamis dari Pakasir API v2, termasuk skema cicilan tahap 2 yang dimonitor di `/admin/pembayaran-tahap2/:id`.
7. Sistem menerbitkan LoA, SKD, kuitansi, dan dossier ZIP.

## Auth dan sesi

Core API memakai HTTP-only Cookie JWT. API melacak sesi perangkat aktif dan bisa mencabutnya, sehingga login lama bisa diputus kalau perangkat hilang. Panel superadmin berjalan di atas matriks role dan permission per modul, dengan audit trail untuk perubahan penting, broadcast notifikasi, monitoring bot WhatsApp, dan pencarian semantik lewat `Ctrl+K`.

## Verifikasi publik

`/kuitansi/:id` menandatangani kuitansi dengan token HMAC, jadi ID yang diubah tidak lolos verifikasi. `/loa/:registrationNo` memverifikasi status kelulusan tanpa perlu login. Keduanya dirancang untuk dipindai dari dokumen fisik.

## Background work

Pengiriman WhatsApp dipisah ke service Node sendiri memakai `whatsapp-web.js` dan Chromium. API memasukkan job ke BullMQ di atas Redis, worker yang mengirim. Ini menjauhkan panggilan keluar yang lambat dari request path, dan bot bisa dimonitor terpisah dari API.

## Deployment

Docker Compose untuk lokal di WSL2 (`docs/DOCKER_SETUP.md`) dan VPS produksi dengan nginx plus Let's Encrypt (`docs/DOCKER_PRODUCTION.md`). Port lokal: company profile 3000, portal PPDB 5173, superadmin 5174, API 8080.
