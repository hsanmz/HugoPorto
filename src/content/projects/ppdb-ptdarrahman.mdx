## Summary

Admission portal and company profile for Pesantren Tahfidz Qur'an dan Digital Ar-Rahman. One repository holds the public website, the student registration portal, the committee backoffice, the superadmin panel, and the WhatsApp gateway. Every frontend reads from a single Core API, so registration status, committee decisions, and published content come from one data model.

## Context and constraints

Student selection runs through stages that lock in sequence: health questionnaire, document verification, TIU exam, interview, payment, then official documents. If each stage lived in a separate application, candidate status would scatter across systems and drift out of sync. That constraint is why the project is a monorepo with one central API instead of a set of services calling each other.

Two public routes must open without a login because they are scanned from QR codes on printed documents. This shapes the auth design: anything verifiable by the public cannot depend on a user session.

## Architecture

```text
Frontends
  Candidate Portal   (React 19)
  Committee Backoffice (React 19)
  Public Website     (Next.js)
  Admin Panel        (React 19)
       |
       v
Core API (FastAPI)
  Registration | Verification | Examination
  Scheduling   | Payments    | Documents
  Auth/Session | RBAC/Audit  | Search
  Public Verify
       |
       +------------------+------------------+
       |                  |                  |
       v                  v                  v
  MySQL             Redis               WA Gateway
  (source           (cache, queue,      (BullMQ,
   of truth)         sessions)          notify)
```

The architecture centers on one API that owns all domain logic. Frontends are thin consumers. Background work (WhatsApp, scheduling) is offloaded to Redis and a dedicated gateway so the API stays fast. Public verification runs through read-only endpoints that require no session.

## Features

**Candidate registration.** A seven-step guided form with health questionnaire (ten questions), document upload, TIU exam in Safe Exam Browser, Tahfidz and interview booking, QRIS payment with optional installment, and digital signature for LoA and SKD.

**Committee backoffice.** Wave management, document verification, rubric scoring, financial monitoring including second-installment tracking, and official document printing (forms, score sheets, receipts, LoA, SKD, ZIP dossier).

**Platform administration.** Staff accounts, role and permission matrix per module, audit trail for sensitive changes, broadcast notifications, WhatsApp bot health monitoring, semantic search across the platform, and active session tracking with revocation.

**Public website.** Program information, news, facilities, gallery, interactive 3D hero, staff profiles, and unified login portal.

**Public verification.** Receipt and LoA pages that anyone can open by scanning a QR code. Receipts carry an HMAC seal so tampered identifiers are rejected.

**Background notifications.** WhatsApp messages enqueued via BullMQ on Redis, sent by a separate Node service using `whatsapp-web.js` and Chromium. Keeps slow outbound calls off the API request path.

## Auth and sessions

HTTP-only Cookie JWT sessions with device tracking and revocation. The superadmin panel enforces an RBAC matrix, records an audit trail, and monitors active sessions.

## Deployment

Docker Compose for local (WSL2) and production (VPS with nginx and Let's Encrypt). Local ports: public site 3000, PPDB portal 5173, superadmin 5174, API 8080.
