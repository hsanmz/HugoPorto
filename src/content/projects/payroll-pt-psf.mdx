## Summary

A payroll system for PT Pangestu Suryaning Famili, used internally by the company. The code is private, so this page covers the product, the system design, and the monthly workflow.

## Context and constraints

Payroll depends on attendance that must always be current. If attendance and salary calculation lived in two systems, they would need a sync step that can fail or fall behind. That constraint shapes the whole application: one application, one database, one panel.

One Laravel application owns the entire payroll domain. Employee data, attendance, salary components, payroll runs, and payslips all live in the same MySQL database. The admin panel is the single interface for every payroll task.

## Features

**Employee management.** Complete profiles with contracts, positions, grades, and salary components (base pay, allowances, deductions).

**Attendance tracking.** Daily logs, leaves, overtime, and shift assignments tied to each employee. Data stays current because it is entered in the same system that calculates payroll.

**Payroll engine.** Defines salary components, allowances, deductions, and tax rules. Runs the monthly calculation from the collected attendance and produces a payroll register.

**Period management.** Open and close payroll periods with lock dates so no changes slip in after a run.

**Payslip generation.** Per-employee PDF payslips with email delivery, bulk export, and re-print capability.

**Reporting.** Payroll register, tax reports, and summary dashboards for finance and HR.

**Settings.** Pay grades, component definitions, schedules, and holidays all configurable in the admin panel.

## Monthly workflow

1. Staff add or update employee records and salary components.
2. Attendance is recorded daily throughout the month (logs, leaves, overtime).
3. At period close, staff run the payroll calculation from the collected attendance.
4. The run produces the payroll register, individual payslips, and summary reports.
5. Payslips are distributed (PDF, email) and the period is locked.

## Design decisions

**One application, not two services.** The salary calculation reads the records staff just edited. Keeping attendance and payroll in one database removes a sync step between services.

**Single admin panel.** Operators stay in one place for the whole payroll cycle.

**Period locking.** Once a period is closed, attendance cannot be modified, preventing silent drift.
