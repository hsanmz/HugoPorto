## Ringkas

Platform belajar berbasis AI, dibangun sebagai monorepo. Frontend, backend, dan perangkat QA ada dalam satu repo supaya perubahan API dan UI bisa rilis bersamaan. Ini proyek akhir program AI-Enabled Python Web Dev di Devscale.

## Konteks dan batasan

Fitur AI tidak bisa berjalan di request path biasa. Chunking dokumen, embedding, dan panggilan model makan waktu detik sampai puluhan detik, jadi pekerjaan itu harus keluar dari siklus request dan response. Kualitas jawaban juga sulit dinilai setelah rilis kalau tidak ada jejak, jadi observability dijadikan bagian dari build, bukan tambahan belakangan.

## Arsitektur

| Layer | Stack | Peran |
| --- | --- | --- |
| Frontend | React 19, TypeScript, Vite, TanStack Router, Ant Design, Tailwind CSS, Framer Motion | UI untuk siswa dan pengajar |
| BFF | Express, PM2 | Proxy panggilan browser ke API |
| API | FastAPI, Python 3.11, Uvicorn | Logika bisnis dan endpoint AI |
| Data | MySQL 8.4, SQLModel, Alembic | Data aplikasi dan migrasi |
| Queue | Redis 7, Celery | Job background |
| AI | ChromaDB, OpenAI, Chonkie, Langfuse | Retrieval, generation, tracing |
| Auth | JWT (python-jose), Google OAuth, bcrypt | Login dan sesi |

Browser memanggil BFF, BFF meneruskan ke FastAPI. API membaca MySQL, melempar pekerjaan lambat ke Redis dan Celery, dan memakai ChromaDB untuk penyimpanan vektor.

## Jalur AI

Chonkie memecah dokumen jadi chunk, ChromaDB menyimpan embedding, dan OpenAI ada di sisi generation. Langfuse merekam trace LLM dan latency probe, sehingga tim bisa menelusuri kenapa sebuah jawaban berubah setelah deployment tanpa menebak.

## Local stack

`docker-compose up -d --build` menyalakan frontend, API, Redis, Celery worker, MySQL, dan phpMyAdmin dalam satu jaringan bridge (`luminaprep-net`) dengan volume MySQL di `./dbdata`.

| Layanan | Alamat |
| --- | --- |
| Frontend | `http://localhost:3000` |
| API | `http://localhost:8000` |
| API docs | `http://localhost:8000/docs` |
| Scalar reference | `http://localhost:8000/scalar` |
| phpMyAdmin | `http://localhost:8099` |
| MySQL | `localhost:3363` (user `user_lp`, db `db_lp`) |

## QA dan observability

Folder `qa` menyimpan test plan, runbook, latency probe, dan trace Langfuse. Rencana uji dan jejak LLM disimpan di repo yang sama dengan kode, jadi hasil pengukuran bisa dirujuk saat meninjau perubahan.
